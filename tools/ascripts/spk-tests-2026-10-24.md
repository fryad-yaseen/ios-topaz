# Speaker vs working headphone investigation, 2026-10-24

No phone operation, build, image generation, flash or push was performed. Scripts target the existing build18 kernel. These are unrun hypotheses, not fixes proven on hardware.

## Evidence and limits

Inputs: logs/as/hph-tone-b18-2.txt, logs/as/spk-on-rx0.txt, android-ref/bolero.txt and wcd-csr.txt, android-ref/swr/*-play.txt, vendor-audio/mixer_paths_bengal_idp.xml, saved upstream wcd937x-upstream.c/.h, wcd937x-sdw.c and wcd-clsh-v2.c, patch1032 interpreter and applied build18 TopazAudio.cpp. Paths are relative to /home/fryad/ios-build except kernel patches/scripts under wt-touch.

The accompanying spk-hph-register-comparison-2026-10-24.tsv contains every RX/WCD/SWR master/slave address observed in either first-tone log. compare-speaker-hph.py reproduces it. It stops before shutdown or later iOS stream reopen, takes the last pre-shutdown readback per address, and labels missing reads unobserved. RX Android bolero addresses subtract0x1000. There are92 HPH addresses,154 speaker addresses,49 common and18 differences. Some HPH values come from checked masked-write readbacks rather than periodic reads. This is all available state, not a full simultaneous register dump. Unobserved HPH DP4 values must not be treated as measured zero. HPH kernel code disables DP2/3/4, whereas speaker master DP4 is enabled but slave DP4 channel enables are zero in the Android reference and speaker run. That is suspicious for AUX, although Android proves this dump combination can occur during speaker playback and mono EAR alone should still work.

## Routing and upstream events

The exact port map and event references are in ear-aux-upstream-2026-10-24.md. wcd937x-sdw.c22-30 and header503-506 map DP1 bit0 to HPHL/RX1, DP1 bit1 to HPHR/RX2, DP4 bit0 to AUX/LO/RX3. EAR3450 bit0=0 selects RX1/DP1 bit0; bit0=1 selects RX3/DP4 bit0. EAR already uses the HPHL-proven slave DP, so a purported separate EAR-port remap would be misleading.

Android speaker XML2401-2415 selects AIF2 RX2/RX3, INT0/INT2, EAR RX1 and AUX, HP_MODE, RX_EAR ON. Headphones2572-2584 select AIF1 RX0/RX1 and INT0/INT1 plus HPHL/R RDAC. Android global HPH mode is CLS_AB and companders are off.

Upstream EAR DAC481-534 enables RX clock,344e bit2,3409 bit0, waits5ms, clears30a4 bit2 and invokes EAR class-H PRE_DAC. EAR PA774-843 sets WD low3=3,300b bit7, widget300a bit7, waits6ms and sets3008 bit1. These main enable bits are already present. HPH30d9 bit7 clear is absent from the EAR event, so it is not an established missing EAR step.

AUX DAC536-564 sets3408 bit2,3128 bit4,3409 bit2,344f bit0. AUX PA715-769 sets WD3467 low3=7, widget3128 bit7, waits1ms, sets3008 bit1 then bits6/7. Current HP_MODE route has3128 bit4 clear and WD5, matching Android steady state. Testing upstream startup is justified but cannot explain EAR silence by itself.

Shared v3 EAR power in wcd-clsh-v2.c715-740 matches HPH's regulator/flyback/force-IQ/current/buck sequence. Successful HPH stages3008=01->41->c1->c3 with delays; speaker ref writesc3 before PA enable. Existing patches1006/1031 already attempted power/PA sequences, which lowers confidence in this hypothesis. Final-state equality cannot establish that the needed transitions occurred in the required order.

## Ranked experiments

1. spk-supply-rearm.as. Replay explicit PA-off shared CLS_AB supply transitions, then EAR/AUX PA events. Best candidate for a common EAR+AUX failure despite final-state equality. Does not enable HPH PA or change transport.
2. spk-inp0-rx0.as. Only changes INT0 from50 to05 relative to the silent RX0 test. Tests the exact successful HPH INP0 leg into the already shared DP1/EAR source. AUX remains the previous control.
3. spk-dp1-stereo.as. Match both master and slave DP1 mask3, both banks, and switch banks0->1. Retain DP4 and all speaker analog settings. Mono mask1 is valid on Android, so lower confidence. Checks bank status, but interpreter cannot abort on bad readbacks; verify104c after each switch is0 then1 before interpreting silence.
4. spk-aux-dapm.as. Cycle AUX PA and apply upstream DAC bit4 / WD7 startup together. This tests the upstream AUX event as a unit. Android ends with bit4 clear/WD5, so a positive result needs follow-up to separate the two changes. EAR stays the previous control.

All retain known RX0 graph intf1/port1/dma_index3,1kHz5s peak3277, normal speaker base, and120s autoreboot. Each collects RX, master/slave DP1/DP4, WCD clocks/reset/PA/watchdog/status and both FS statuses every500ms. Kernel shuts down PAs/amps before @stop; stereo script restores port masks then. All are under8192 bytes,128 commands and160 characters per command. Read counts1..8; MMIO addresses aligned and within LPASS whitelist. Static validation only. Test each in a separate boot. Audibility plus FS state is the result; latched configuration alone does not prove signal delivery.
