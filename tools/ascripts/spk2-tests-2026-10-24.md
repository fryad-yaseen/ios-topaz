## Findings

Sapphire's XML and Android event logs support EAR -> FS34 -> top speaker and AUX -> FS35 -> bottom speaker. This identifies software routing, not a measured schematic. mixer_paths_bengal_idp.xml2401-2436 splits speaker-top EAR and speaker-bot AUX. resourcemanager_bengal_idp.xml576-591 maps handset to RXTX RX0, mono48k/16bit. handset XML2511-2523 selects EAR, RX1 RDAC, RX0 INP0, volume84 and EAR external amp Receiver mode. The earpiece therefore uses EAR through the external-amp route. It is not an independent bare-WCD EAR control. A working handset-style test would establish the entire EAR/FS34 branch works; silence cannot identify which part fails.

Neighbor topaz wcd937x.c2778-2780 only has FS1815_DEV_0 after AUX PGA. Do not use that single-amp DAPM wiring to override sapphire's two-amp logs. dmesg-speaker.txt771.809253 has class-H0->1,771.812986 has1->9,771.829548 EAR POST_PMU,771.829638 FS34 scene000C0000,771.829647 switch1,771.829651 stub state0;771.840747 AUX POST_PMU,771.840789 FS35 scene00030000,771.840792 switch1. About11ms separates amp starts. Shutdown787.620/787.631 reverses each switch with state1. AW callbacks fail because no AW device exists; they are not the successful speaker driver. Full dmesg209.649-209.715 initializes35 then34, both tcoef229, trim fallback; addresses have positions01 and08. These logs do not expose individual I2C writes or an amp-ready poll.

Published topaz fsm_speaker_onn sets stream_muted=false, initializes if needed, switches scene tables, then calls each start_up. stream_muted is software bookkeeping. fsm_stub_switch_preset optionally shuts down/restarts around table loading; same scene skips. FS1815 start_up writes11=008f,10=0000, calls fsm_config_vol, waits10ms. fsm_config_vol immediately returns for is1820, the flag selected for chip12. No extra volume write is required by this source. Patch1018's optional06=ff00 is therefore not justified by this driver. SYSCTRL008f already contains oscillator, bias, impedance measurement, ADC and amp enables; bit6 BSTPD is clear. Rev11-only BC9433 does not apply to observed rev30. No FS1815 mute/unmute callback, AF/C4 write or amp-ready poll exists on this path. Generic fsm_reg_case supports waits but none occur in the local common/scene tables. See spk2-scene-audit-2026-10-24.md for every decoded unit. 1005/1010 cover common/Music, trim read/fallback, shutdown and startup. Sapphire's newer v4.1.0-a spc-driver-v1 uses per-amp APIs absent from this published source. Its internal switch implementation remains unverified.

## Ranked tests

1. spk2-dp4-enable.as. Highest remaining concrete transport suspicion: previous tests never enabled slave DP4. Current master DP4 is01000107, while both slave DP4 banks have channel0 disabled and timing zeros. Set slave interval7, offset1, lane1 and channel1 in both banks, prepare channel and switch0->1. EAR stays control. Android's selective playing dump also has disabled slaveDP4, so this is a hypothesis about capture timing/port interpretation, not a proven Android mismatch. Require active bank readbacks0 then1; inspect slave values and any SoundWire errors before interpreting silence. AUX sound or FS35 moving to000D/7580 supports missing DP4. This alone cannot explain the prior EAR failure.
2. spk2-ear-only.as. Disable AUX PA/watchdog and FS35; keep EAR/FS34 and known-good RX0/INP0, use handset-like RX -18dB. Tests whether simultaneous AUX/shared state prevents EAR operation. Retains FS34 Music. It is deliberately a partial handset test: exact Receiver mapping is unresolved and no Receiver capture exists. Keep stereo graph because build18 tone_test writes interleaved stereo regardless of graph.channels; setting channels1 alone would misdescribe the ring. Sound supports EAR/FS34 usability; silence does not prove WCD EAR alone is broken. AUX should remain silent and FS35 off.
3. spk2-music-replay.as. Reload Music after graph/codec activation, then start34, wait10ms, start35. Earlier rearm preserved tables. Full-register equivalents for masked scene fields use captured Music baseline3f0110,bc1423,590821,19=000b/000e. Inspect readbacks. This tests late scene timing or lost scene writes; it does not reveal the newer closed per-amp implementation. No reset, no BC bit3 forcing, AF/C4 or undocumented enable writes. Lower likelihood because tables/startup already exist and rearm failed.

All use build18 speaker base and120s autoreboot. Run each separately only when hardware work is authorized. Compare audibility, FS03/04, WCD state and script errors. Status flags remain undocumented. A positive change does not by itself assign meanings to ANASTAT bits. If all fail, the next useful evidence is a matching Android Receiver/amp-register capture or verified analog measurement at EAR/AUX and amp input, not another guessed enable register.
